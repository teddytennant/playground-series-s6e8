=== THE TARGET: is the h3/ens4 public-LB reversal ONE draw or TEN? ===

The w21 addendum §10 calls this "the strongest live threat to the deadline pick" and says
it "deserves a slot of its own, not a paragraph". Both deadline picks are h3-side. The
standing defence is w16s §3: a public-sized slice reverses a true ~5e-6 h3 advantage with
probability 0.244, and the observed run of reversals "is ONE draw against a fixed slice".

That defence has never actually been TESTED. w16s computed the MARGINAL reversal
probability for two pairs separately. It asserted, but did not measure, that the pairs are
so correlated that the run counts as a single observation. That assertion is the entire
load-bearing element and it is checkable locally for free, because the JOINT distribution
of all pairs on the SAME simulated slice is exactly what the instrument already draws.

FIRST, A COUNT CORRECTION registered before the measurement: the journal says 8/8. Pairing
lb_scores.json with the five newest API rows, there are TEN h3/ens4 pairs with BOTH sides
scored on the public LB and BOTH sides available as stored OOF:

  blend156, blend158, blend159, blend159av, blend160orig, blend160origm,
  w14a_repro159av, (w16i_schemeavg vs w16q_ens4avg), w20_ad187, (w21_ad187corr vs _ens4)

and the h3 side is one 1e-5 reporting step BELOW the ens4 side in all ten. So it is 10/10,
not 8/8. Registered here so the correction cannot look like it was tuned to a result.

A LOGICAL POINT that removes the rounding objection before it is raised: rounding to 1e-5
is a monotone non-decreasing map, so round(a) < round(b) IMPLIES a < b. Every one of the
ten observations is therefore HARD evidence that h3's true public-slice score is strictly
below ens4's. There is no rounding-cell ambiguity in the DIRECTION, only in the magnitude.
This makes the joint question the only question.

MEASUREMENTS, fixed now:

  M1. Per pair, the CV delta (h3 - ens4) on full-train OOF. Expected all positive.
  M2. 2000 reps. Each rep draws ONE index permutation, takes a public-sized block
      (59,260 = round(296,302 * 0.20)) and its private-sized complement (237,042), and
      scores ALL TWENTY files on BOTH. Same protocol, seed and f as w16s/w16k so the
      numbers are comparable to the record; REPS raised 500 -> 2000 because a JOINT tail
      probability needs far more reps than a marginal mean.
  M3. Marginal P(pair reverses on a public-sized slice), per pair. GATE: the two pairs
      w16s already published (blend159av at 0.244, w16i/w16q at 0.248) must reproduce
      inside sampling error, or this is not w16s's instrument and nothing below stands.
  M4. THE HEADLINE: joint P(ALL TEN reverse on the same slice), and the full correlation
      matrix of the ten slice-level deltas.
  M5. THE PART THAT ACTUALLY PRICES THE THREAT, and which no run has done: public and
      private are DISJOINT COMPLEMENTARY halves of one fixed test set. If a slice happens
      to favour ens4, the complement is mechanically pushed toward h3. So the
      decision-relevant quantity is not P(public reverses) at all, it is
          P(h3 wins the PRIVATE complement | the public slice reversed, all ten)
      together with corr(public delta, private delta) across reps. Report both.

  R1. If M4's joint probability is close to M3's marginal (say >= 0.15), the ten pairs are
