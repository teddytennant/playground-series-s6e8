WHAT IS BEING DONE ABOUT IT, and why not the obvious thing
----------------------------------------------------------
The obvious thing is to kill the 199 build and restart it at 197. **That is refused.** The rule
was fixed before the number existed (git 2d1eff1), the number arrived, the rule fired. Changing
the pack now because the result is not the one I would have preferred is post-hoc pack
selection — the exact failure the pre-registration file exists to prevent, arriving through the
back door of "but the stricter rule was the right one". The cost of letting it stand is small:
the ravi pair is a NULL, not a measured negative, so it dilutes rather than damages.

Instead the conflict is converted into a measurement. ARM 197 (ram pair only, no ravi) is
queued as `w36g_run.sh` behind the ram paired instrument. The 199-vs-197 difference IS the
ravi pair's value on the shipping instrument, which is a better answer than either rule.
